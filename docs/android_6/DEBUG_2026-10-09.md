# H6 root ADB 音频、USB 与左栏调试（2026-10-09）

## USB 所有权

依据用户提供的 [Legacy Android README](https://github.com/programmerguohuajing/DiPlay-Legacy-Android/blob/main/README.zh-CN.md) 排查原车后台投屏。IHU01/API23 的 CarLife 包为 `com.baidu.carlifevehicle`，随 USB 事件重新启动；原车 native 服务还有 `usbnetd`、`iAP2SV`（iAP2Test）、`MFI_AU`（mfi_auth）。文件描述符检查未发现它们持有 iPhone USB 节点；MFI_AU 持有原车 `/dev/iap_mfi`，这不等于 USB 接口占用。

实车默认配置2的接口2.0/2.1绑定 `snd-usb-audio`，2.2绑定 `usbhid`，出现iPhone USB声卡。正常断开后恢复配置2，在同一手机上 `am force-stop com.baidu.carlifevehicle` 后三个驱动仍绑定，配置仍为2。由此确认停止 CarLife 不足以解除本机占用；没有证据把它认定为唯一占用进程。继续使用现有单次接口释放及正常断开恢复，不停用原车核心服务或全局卸载驱动。

升级code33后经历一次旧会话握手失败及多次USB设备消失。内核记录 `device descriptor read/64, error -71`，此时系统没有iPhone设备，无法做音频判定。用户重新插紧并执行接口释放后恢复配置6、认证与视频；不能把这段准备失败归于静音输入候选。

## code33 音频实车进展

覆盖安装同签名code33，保留配对/设置；首个有效会话21:34:46接受type100，建立48kHz stereo LPCM媒体音轨，随后type110首帧。用户确认车机音乐与导航都出声。type101导航协商为8kHz mono LPCM。真实麦克风仍关闭，不创建AudioRecord。

这证明code33条件下音频链路可建立，但缺少同一线缆状态/后台状态的code32再对照，尚不能把全部根因唯一归于输入声明。iPhone控制中心输出列表未单独确认。用户报告音乐不流畅，导航期间明显卡顿，因此不是完整音频稳定性验收。

21:36附近媒体RTP缺包26+76=102；系统 `Udp6RcvbufErrors=102`，随后又有6个序列缺包，是否对应系统计数另采对照。应用媒体队列丢弃与AudioTrack写入错误为0，出现一次rebuffer；媒体与导航均保持mobile usage路由、单一媒体焦点。不能仅加大AudioTrack缓冲掩盖UDP入口丢包。

内核 `net.core.rmem_max=163840`，默认值也是163840。应用请求524288，但实际socket buffer为327680（Linux记账包含倍增），被上限约束。驻车root实验保存原值和计数，正常断开后仅将rmem_max临时设为524288，默认值不改、不写启动配置。新socket实际缓冲1048576；新会话持续播放/导航期间系统Udp6RcvbufErrors保持102，用户确认音乐与导航已流畅。该上限仅当前运行有效，车机重启后需重新应用；尚未实现普通UID的无root长期解法。恢复命令为 `adb shell 'echo 163840 > /proc/sys/net/core/rmem_max'`；恢复上限不缩小已经创建的socket，完整基线对照需要重新建立会话。

## DiPlay/高德全屏与code35主页回退

物理屏幕1280×720、160dpi；系统左侧NavigationBar为[0,0][120,720]。百度地图主窗口[120,0][1280,720]，DiPlay主页及投屏[0,0][1280,720]。只读分析厂商PhoneWindowManager.layoutWindowLw发现它对com.baidu.naviauto等包直接设置left=120，其他应用没有该特例；标准insets及清理全屏标志不足以得到相同窗口。

用户明确投屏必须全屏、仅保留CarPlay侧栏，并确认高德也要隐藏原车左栏。root ADB设置全局policy_control的显式包过滤器：

```sh
adb shell 'settings put global policy_control immersive.navigation=com.shihab.diplay.hudtest,com.autonavi.amapauto'
```

它仅对这两个包隐藏系统导航栏，原车桌面/百度地图等不受过滤器影响。该设置会保留，初值null；撤销用 `adb shell 'settings delete global policy_control'`。该策略也适用于DiPlay主页，不能以包过滤器只覆盖同包的投屏Activity。应用本身不写系统策略或获取额外系统权限。

code34实车确认系统NavigationBar的policyVisibility=false，投屏保持1280×720。用户确认CarPlay地图/音乐App可切换，画面与音频正常。高德打开后截图确认原车左栏隐藏、左侧搜索区域完整露出；点击验收单独记录，不把截图当触摸保证。

最终code35恢复CarPlay原全屏偏好。H6SystemBars仅用于主页及裁剪页：若无显式包级隐藏策略，使用configuration.screenWidthDp换算宽度靠右，避免厂商没有左侧inset时按钮遮挡；若已由ADB显式隐藏本包导航栏，窗口使用全宽，避免重复预留。投屏videoView尺寸与触摸映射保持原实现。未修改全局wm size/overscan、高德APK、USB读泵/NCM、音频格式或焦点实现。
