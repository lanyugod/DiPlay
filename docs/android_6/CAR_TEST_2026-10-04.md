## VPN：已验证框架，但权限属于每一个包

探针上次通过额外临时授权验证了TUN建立/释放，授权随后已撤销。
它的包名为 `com.shihab.diplay.android6probe`，不会给主体 `com.shihab.diplay.hudtest` 授权。
该固件缺少 `com.android.vpndialogs/.ConfirmDialog`，所以安装主体不会自动补出系统授权窗口。

主体新增“重新检查连接权限”：外部授权完成后无需重新安装；弹窗即便返回成功也再次核验本应用真实授权。
先尝试正常连接并接受系统授权。如果仍提示缺少权限，需在车机端为主体完成一次系统/外部授权，这是设备操作，不是继续采集探针数据。

设备所有者沿用此前已验证的ADB授权方式时，先读取并保存原模式，再仅针对主体包设置：

```sh
adb -s 192.168.43.1:5555 shell appops get com.shihab.diplay.hudtest ACTIVATE_VPN
adb -s 192.168.43.1:5555 shell appops set com.shihab.diplay.hudtest ACTIVATE_VPN allow
adb -s 192.168.43.1:5555 shell appops get com.shihab.diplay.hudtest ACTIVATE_VPN
```

地址按当天实际连接修改。上次恢复重启后该固件的普通shell返回closed但exec-out可用；遇到同一情况，可用 `adb -s <设备地址> exec-out appops ...` 执行相同命令。应用自身不会执行提权命令。返回主体点击“重新检查连接权限”。若当天完全没有系统授权入口或ADB/其他受支持外部授权方式，有线流程仍会停在VPN权限处。

## 明早测试顺序

1. 驻车安装上述standalone APK，确认兼容配置为H6 Android6有线；确认进入连接页不再提示认证文件缺失。
2. 完成主体自己的VPN授权；缺窗口时按上节操作，再点“重新检查连接权限”。
3. 退出原车投屏，解锁iPhone，用数据线连接并接受主体的USB/手机提示。记录是否出现CarPlay画面。
4. 如提示USB配置或接口不可用，拔插后点“重试USB连接”；仍失败则导出主体诊断。错误会停止自动重连，不循环强抢接口。
5. 首次成功后依次测触摸、音乐、导航播报、回桌面再返回、拔插重连。保留手机型号/iOS、发生时间与诊断文件。

样本解码、短音与电脑回归不替代完整会话。首次连接稳定后再依详细设计完成倒车/原车音源共存与两小时稳定性验收。
